# Changelog

## Unreleased

- **Hermes interfaces UNBL0CK depends on are listed, checked and fail clearly (#44).** `needs.HOST_API` lists every non-public Hermes name the source uses (a test keeps it equal to the code), `needs.host_compat()` reports which are present, and the queue adds one plain `host:` line to its errors when a Kanban read fails and the host lacks interfaces. `scripts/host_compat.py` prints a counts-and-names acceptance record (versions, OS, lock mode), and docs/verification.md gains an acceptance matrix that marks every live receipt not run until someone runs it on the real host.
- **Windows gets a cross-process state lock, with its evidence stated (#43).** Hidden, summary, pending-release and filed state now take a byte-range lock on the shared lock file on Windows (the same file, five-second timeout and private permissions as the macOS/Linux `fcntl` lock), `needs.state_lock_mode()` names which lock applies, and the lock file is never deleted. Real concurrent-process tests cover all four stores on macOS/Linux; the Windows path is tested against a simulated lock only and is not yet run on a real Windows host.
- **A provider integration plan and adapter contract, with nothing connected (#39).** `docs/provider-integrations.md` fixes what an adapter must promise (identity, permissions, provenance, stable ids, deduplication, incremental reads, changed items, deletion, completion and reopen, revoked access, rate limits, reading versus writing) and proposes a provider matrix (wave 1: generic IMAP drafts, Gmail, Microsoft Graph; wave 2: CalDAV tasks, Notion). `adapter_contract.py` holds the rules as pure, unwired code and `tests/test_adapter_contract.py` runs them against a fake adapter, including that an agent's filed completion is never shown as confirmed at the source. No connector, account access or network call is added.
- **HTML-only mail is readable, mail is not always a draft, and unread formats are reported (#38).** An `.eml` with no plain body now shows inert text from its HTML (nothing rendered or fetched; scripts, styles, frames, hidden elements, links, image sources and alt text dropped; no attachment is substituted), marked "Converted from HTML". Purpose comes from the message's own headers: unsent markers mean draft, received-mail headers mean an ordinary message, anything else follows the new `outside_eml_kind` setting (default `draft`). `.msg`, `.mbox`, documents, standalone HTML and audio in a watched folder are counted in the queue errors (extensions only) instead of vanishing, and the operator guide has a supported-format table. Native provider connectors and further formats are not part of this change.
- **A safe recovery workflow for corrupt plugin state (#48).** New `recovery.py` (stdlib, next to `needs.py`) has `diagnose`, `preserve` and `restore` for `hidden.json`, `pending-release.json` and `bluf.json`. Diagnosis separates corrupt or truncated files, valid JSON in an unsupported shape, unsafe paths and an active writer, and prints counts only. `preserve` copies the exact bytes into `plugin-data/unbl0ck/recovery/` (0700 directory, 0600 files, never deleted). `restore` is a dry run by default, refuses unverified, symlinked, loose-permission or wrong-store backups, never clears the lock, copies the current bytes aside first and swaps atomically; a failure leaves the store as it was. Legacy null or empty hidden versions stay valid. The operator guide and state table describe it.
- **The disclosure matrix says watched-folder and filed items are read across profiles (#42 review).** Agent-filed items sit in one shared folder and the queue has no reading profile, so `outside` is now marked cross-profile in `needs.SURFACES` and the architecture table, and tests check the column against what the readers actually return for two profiles.
- **A source-by-surface disclosure matrix, in code, payload and docs (#42).** `needs.SURFACES` and `disclosure_matrix()` say which sources can reach the model provider by summary, Ask or search, and which are read across profiles; `GET /queue` returns the live matrix as `disclosure` (booleans only), and `docs/architecture.md` carries the table, kept equal to the code by a test. New tests send synthetic secrets through every summary and Ask input, check that only kanban, filed/folder and chat items are summarized, that Ask refuses non-Kanban references, that a settings fault turns every model path off, and that summary caches stay partitioned by source and profile and survive concurrent saves and corruption. The independent Security verdict for the exact head is not part of this change.
- **Chat coverage no longer claims more than was read or summarized (#40 review).** Full-text search reports chat sessions the scan cap left unread and is marked partial. A corrupt chat database or unreadable settings now shows a failed chat source with a plain note instead of "Chats checked: last N days". Chats found only because `chat_window_days` reaches past 14 days are marked backfilled and are never sent to a model for an automatic summary.
- **The queue says how far back it looked and what it cannot see (#40).** The payload carries `coverage`: the chat window actually read, sessions checked and left unread, chats skipped by the group-name and owner rules (counts only), and fixed sentences on what an empty list does not prove (older chats, unnamed group asks, non-English asks, Kanban comments). Desktop shows them under the list. New `chat_window_days` setting (default 14, 1 to 90) is a bounded read-only backfill: at most 500 sessions per profile, hidden items stay hidden, no duplicates. `tests/ask_corpus.py` is a labeled corpus (39 cases across sources, platforms, five languages, name forms, indirect and group asks) whose test pins the known false positives and negatives so a fix or a regression both show up.
- **Search is tested at the profile boundary and for preserved state (#45 review).** Tests show full-text search finds exactly the chats the queue shows for every profile under the Hermes home, returns ids, versions and sources only, and that the Search full text button changes only its own search state, so typed answers, drafts and open conversations are left alone.
- **Full-text search spends its budget on cards a person can see and counts only what it examined (#45 review).** Chats, live prompts and filed items dismissed at their current version are dropped before the 200-item limit and before any full-text expansion, so 200 hidden chats no longer hide a visible one. All watched folders share one read budget of 200 files (the rest are reported as not searched) instead of reading 200 per folder. A watched-folder file cut at its read limit is counted as cut and makes the result partial. Password prompts are counted as skipped, not as searched.
- **Full-text search counts text the chat and prompt readers already cut, and expands only what it searches (#45 review).** A term beyond the 20,000-character cap of a chat message or live prompt now shows as `items_cut` and `partial` instead of a clean "no match". The readers expand full text for the first 200 items of a source only; the rest are still counted as not searched, so a 205-chat inbox no longer does 205 full-text expansions to report 200 searched.
- **Search says what it searches and can go deeper on request (#45).** The filter box is labelled as searching titles and previews of the cards loaded here. A separate **Search full text** button makes one `GET /search?q=` call that reads the stored text of chats, live prompts and filed or folder items, at most 200 items and 20,000 characters each, 8 terms and 200 query characters. Results carry the source and item version, and a coverage line reports what was searched, not searched, cut off or skipped (password prompts are never read) and which sources failed. It is read-only, never calls a model, never runs on a timer, and leaves typed answers and open conversations alone.
- **Limited surfaces say what they leave out (#47).** The CLI and local slash list now end with "Not listed here: N stuck, M answered", and an empty list with stuck or answered cards is no longer reported as an all-clear. The remote slash command adds the same counts and still carries no title, text, name, id or command. The Pocket pack gains an `omitted` object (asks beyond six, stuck, answered, and where to look) of counts only. The operator guide has a five-surface matrix and `tests/test_surface_contract.py` pins common item order and identity plus every intentional difference.
- **A capability matrix says what each source can do and why not (#33).** The queue payload publishes `capabilities` (Kanban, chats, live prompts, pairing, filed items, watched folders) separating built features from intentional safety restrictions and from real gaps; the operator guide shows the same table and a test keeps them equal. Cards without TL;DR now say "TL;DR is not offered here" with the reason (password prompts and pairing are never sent to a model). No inline reply, send or approve was added: replies still happen in the original surface under its own authorization, and a test pins the set of write routes.
- **Ask restart markers distinguish unavailable storage from a missing marker, and one bad entry no longer disables them (#35 review).** The model call starts, and a discard reports success, only after the marker is verified absent; storage that cannot be examined counts as unknown. A dangling symlink named like a record is judged without being followed, is removed by housekeeping and no longer makes every new marker fail.
- **Deleting an Ask job reports failure honestly and the restart-marker cap holds (#35 review).** When the saved record cannot be removed (for example a read-only directory), `DELETE /card/ask/{job}` now answers 500 and leaves the job as it was instead of reporting success and letting the next GET recover the saved answer. A new marker first evicts the oldest ones that no live job owns, so the 256-file cap holds across gateway restarts rather than overshooting until the next throttled prune.
- **Ask survives a gateway restart without resending (#35).** Each Ask job leaves an owner-only restart marker (0600 in a 0700 directory, 256 files, 15 minutes, no card or answer text) so a poll after a restart reports `pending`, `complete`, `failed`, `unknown` (sent, outcome not knowable) or `not_submitted` (nothing left the machine); the plugin never resends and Retry is the human's decision. Job ids answer only for their own card, `DELETE /card/ask/{job}` removes a job at once, corrupt or symlinked markers read as unknown, and an unwritable directory falls back to memory. New opt-in `ask_persist_replies` (default off) keeps finished answers on disk for the retention window.
- **A superseded Ask request stops polling and cannot hand Retry its job (#34 review).** When the running session is evicted while the card is mounted and a second question starts, the older request now exits at its next step instead of recording its job id over the newer one or appending its answer to the newer conversation.
- **Ask conversations survive filtering, source outages and route remounts (#34).** The conversation, a running request and its job are kept in bounded Desktop session memory (100 conversations, 30 minutes, never written to disk), so returning to a card shows the answer without a second model call. Recovered conversations stay bound to their question version and a late response cannot overwrite newer work. Reload still clears them by policy.
- **Records filed by 0.6.0 before profiles existed keep their Done and Not for me state (#46).** Adopting an ownerless record into a profile keeps its version when the content is unchanged, so an unchanged refile no longer resurfaces finished work; key-only resolve finds it. Tests start from the exact record 0.6.0 wrote.
- **Filed dedupe keys are profile-scoped by default (#46).** `unbl0ck_file` takes `dedupe_scope` (`profile` or `global`); the same key in two profiles now files two items and one profile can no longer replace or resolve another's by key. Records and replies carry `dedupe_scope` and `profile`; legacy records are adopted in place by their own profile without resurfacing a local Done.
- **The folder scan's time budget also covers empty directories (#37 review).** The deadline is checked before each queued directory is opened, so a tree of empty folders can no longer scan past the 2-second budget without the "stopped after" notice.
- **Folder paging keeps its progress and overlapping roots lose nothing (#37 review).** Folder Done records have their own 5,000-entry bound in `hidden.json` (other dismissals stay at 1,000), so finishing a backlog past 1,200 files no longer evicts the earliest completions and cycles back to them; a file is claimed by an overlapping root only when it is actually shown, so an older file under a separately watched child folder is no longer dropped.
- **Hiding the first page of a watched folder no longer strands older files (#37).** Done and Not for me files no longer use the 200-file window, ties order by path, and the queue reports how many older files are waiting. Optional `outside_recursive` reads nested folders within depth, entry and time limits, never following symlinks; the filed-item cap reports counts and how to continue. Source files are never moved.
- **Undo no longer clears a newer Done, and a failed write stays retryable (#36 review).** A Not for me token for an older version cannot remove a Done recorded for a newer one, and when both markers exist the hidden marker is cleared first so a failed second write leaves the Done token valid for a retry.
- **Undo names the dismissal it undoes (#36 review).** A Done now returns a `token` and Desktop sends it (or the hidden version) with `/unhide`; an old Undo can no longer clear a newer Done or hide, and a filed item dismissed twice (Done in one tab, Not for me in another) is restored by either Undo clearing both markers. Callers without a token behave as before.
- **Done on outside items is local and recoverable (#36).** Done on an agent-filed item now keeps its record, marked done, for 15 minutes (at most 25 records) instead of deleting it, so Undo works; folder Done is unchanged. Desktop keeps a history of the five latest dismissals with separate Undo buttons, announces expired Undo windows, and says "nothing to restore" when an item changed or aged out. The card states that Done does not send or complete anything in the original app; the agent's `resolve` stays the permanent path. Re-filing identical content keeps a Done item hidden, changed content resurfaces it. The stored text of done records is deleted after the window and never printed in errors.
- **Answers carry an explicit version precondition and every route bounds identifiers (#41).** `POST /kanban/answer` now reports the block `version` it applied and whether the caller sent one (`versioned`). Unversioned comment-only answers keep working but get a `Warning` header; the new `require_answer_version` setting (off by default) turns them into a 428 before anything is written. An empty version is a 400. `/card`, `/hide`, `/unhide`, `/outside/done` and the answer route share one 300-character, no-control-character limit, and a malformed, non-Kanban or conflicting card id is a 400 rather than a silent retarget. Stale and retried answers never duplicate a comment or release a newer block.
- **Full text shows the whole chat message or live prompt (#32).** Polling still carries a 480-character tail, now labelled; opening Full text reads the complete record (up to 20,000 characters) for that version via `GET /source/text`. Stale, missing and unreadable sources report errors with retry; password prompts are never expanded and nothing is sent to a model.

## 0.5.1 (2026-11-14)

- **Interrupted Ask responses are recoverable.** Retry polling the same completed job without repeating model work. Completed-result retention is bounded and follows completion order, so a slow job is not immediately evicted by newer requests.
- **Unreadable settings fail closed.** Read errors, parser error markers and loader import failures cannot widen chat visibility, model disclosure or answer identity. Concurrent refreshes share one settled read; another caller's repair cannot erase an in-flight caller's fault. Configured behavior resumes after repair.
- **Typed answers survive a source outage.** Session drafts retain their original question version; a late completion from an old card cannot erase a newer draft. Drafts remain in memory for up to 30 minutes after editing and do not survive a page reload.
- **Mail selection excludes named MIME parts.** Inline parts with filenames cannot replace the message body; alternative and related message structures retain their body-selection rules.
- **Canonical guides cover recovery and review.** Operator, architecture and verification references document the actual limits. A signed external-PR Security Hermes relay is included for owner activation; acknowledgements do not count as review approval, and live activation remains unverified.

- **Recovery survives a temporary outage.** Failed Undo keeps its retry control and cannot submit twice while pending. Failed answers refresh the queue immediately so a posted answer with a failed release shows its recovery action. Long TL;DR conversations keep their displayed history while respecting the API's 50-message transport limit.
- **Failures stay visible and recoverable.** Corrupt source records, schema/config failures and folder limits mark the queue incomplete. Unreadable prompt records survive inspection, stale cleanup cannot hide healthy prompts, and visibility writes refuse corrupt state. Summary fallback status is explicit; model work has bounded admission, rejected submissions cannot strand jobs, and Ask expiry works without a new request.
- **Find cards in a large queue.** Search titles, previews, apps and references, or filter by source. Typed answers survive filtering, and the status count still covers the whole queue.
- **Read and recover in place.** Every card has a keyboard-accessible full-text toggle. Full-text and Context failures have retry controls; folder Done can be undone for 12 seconds. Long subjects and unbroken text wrap on small screens, and text composition no longer submits an unfinished answer or Ask.
- **Exports show the right content.** Plain-text attachments and attached messages never stand in for an HTML-only draft body. Oversized exports disclose the 256 KiB preview limit.
- **Faults stay honest.** The CLI and status chip no longer imply an empty queue is complete when a source fails. Combined `--json --pack` keeps stdout valid JSON. Disabling the Desktop plugin ignores late responses and cannot restart its polling.
- **One click gets the bottom line.** "Ask about this card" is now **TL;DR**: clicking it asks your model, straight away, what the card wants from you and what to pick, in plain words and under 80 words. Follow-up questions still work in the same panel.
- **Ask no longer comes back empty on reasoning models.** With a 900-token cap, MiniMax M3.1 Flash spent the whole budget thinking and returned no text, which showed as "The model returned an empty answer". The cap is now 4000, inline `<think>` blocks are dropped, and a reply with no answer text says so and suggests a retry.
- **Real asks stop vanishing from the queue.** A negation now counts only in the same clause and only in the three words right before the ask, so "Cannot proceed: needs CEO approval to merge" and "Needs your approval. Not urgent." are listed. After the ask, only "is not needed/required" cancels it. New phrasings are recognised: "approval from Ada", "can't deploy without your approval", "Please approve…", "need the human to…". A relayed order ("CEO says: …") still counts as a stop unless it asks for *your* approval or decision. On the live board, 16 of 209 blocked cards are now listed, up from 10.
- **Fewer false chat asks.** Question marks inside URLs, sign-offs like "Anything else you need?", questions the turn answers itself ("Why did it fail? Because…"), "which option was faster" and an archived decision packet no longer count as asks.
- **"Answer, keep blocked" cards stay in the queue.** Before, answering a card without unblocking it made it vanish, so it stayed blocked with no way back from UNBL0CK. Now it stays listed as `answered` (counted apart from new asks, no model summary) with a **Release (unbl0ck)** button that unblocks it without posting a second comment.
- **The shortcut shows what it will do.** When your answer says to keep the card blocked, ⌘/Ctrl + Enter keeps it blocked; the ⏎ mark now moves to **Answer, keep blocked** and the hint says so. The Release button no longer shows a shortcut it does not have.
- **Docs say what actually happens.** Failed summaries are retried after 10 minutes and the page polls every 45 seconds; listing pairing requests prunes expired ones, as `hermes pairing list` does; the CLI points to the `/unblock` page.

## 0.5.0 (2026-11-11)

- **Things waiting outside Hermes (#10).** The new **OUTSIDE.HERMES** queue group collects mail drafts, call notes and other items through the `unbl0ck_file` agent tool or read-only watched `.eml`/`.md`/`.txt` folders (`outside_dirs`, off by default). Agent claims are labelled, filing supports deduplication and resolve, and BLUF summaries include outside text when enabled. Done deletes only UNBL0CK's filed records; folder Done hides until the file changes. No external app APIs, credentials or automatic external actions.

## 0.4.6 (2026-11-11)

Fixes from the hackathon roast (two independent audits).

- **Your answer goes to the question you read.** The desktop sends the queue item's version with each answer. If the card was blocked again after you opened it, the answer is refused (HTTP 409) and nothing is posted.
- **A failed unblock can be retried.** When the answer posts but the card won't unblock, the card stays in the queue marked `release_failed`. Answering it again retries the release without posting the answer twice. The marker lives in `plugin-data/unbl0ck/pending-release.json`.
- **Every blocked card is listed** (from PR #1): cards with no recorded ask show as `stuck`, with the reason. Answered cards leave the queue in both tiers. Stuck cards don't get a model summary, so a long stuck list doesn't trigger a model call per card.
- **State files are safe across processes.** `hidden.json`, `bluf.json` and `pending-release.json` are written under a file lock, so the dashboard and the agent plugin no longer drop each other's writes. A failed write no longer leaves a temp file behind.
- **The owner filter fails closed.** With `owner_user_ids` set, a gateway chat whose user is unknown is no longer shown or summarised.
- **`GET /pack` is read-only.** `POST /pack` writes `pocket-pack.json`.
- **No personal names in shipped files.** Tests and the design canon use generic names.
- **CI runs the tests in the pinned Hermes runtime** with a throwaway `HERMES_HOME`, and fails if any test is skipped.
