# Changelog

## Unreleased

- **HTML mail is converted by the cascade, hides what it should, reads what it should, and says what it left out (#38 round 4).** Hidden text is now decided by whole property names, CSS comments, `!important`, zero opacity written any way, and `<style>` rules with tag, class, id, descendant and child selectors; a visible child of a `font-size:0` or `visibility:hidden` parent is read, and a textarea's text is shown. An omitted `</head>`, a self-closing `<script/>`, nesting past the tracked depth, an oversized character reference, an unterminated comment or quoted value and a reader failure no longer lose or leak text silently: the card says part of the body is not shown, and says when styles could not be evaluated. A plain part holding only zero-width or control characters no longer beats the HTML body. The guide, README and manifest now state that a tracking address printed as text stays, what the converter evaluates, and that an unsent marker wins over received-mail headers.
- **A hidden or never-closed HTML element no longer makes a mail look empty (#38 sweep).** When one swallowed the rest of an HTML body, the card said the message had only attachments. It now says part of the body is not shown because it sits inside a hidden or never-closed element, and keeps whatever text came before it.
- **HTML-only mail is readable, mail is not always a draft, and unread formats are reported (#38).** An `.eml` with no plain body now shows inert text from its HTML (nothing rendered or fetched; scripts, styles, frames, hidden elements, links, image sources and alt text dropped; no attachment is substituted), marked "Converted from HTML". Purpose comes from the message's own headers: unsent markers mean draft, received-mail headers mean an ordinary message, anything else follows the new `outside_eml_kind` setting (default `draft`). `.msg`, `.mbox`, documents, standalone HTML and audio in a watched folder are counted in the queue errors (extensions only) instead of vanishing, and the operator guide has a supported-format table. Native provider connectors and further formats are not part of this change.
- **Operator recovery refuses linked data directories, reads backups as bounded plain files, reports honest results, and its documentation matches (#48 round 4).** Restore rebuilds its plan under the lock, installs only the file it wrote and verified, and reports a failure after the swap as `failed` with `store_unchanged` false. Diagnose lists at most 100 backups within a size and time budget, and the guide now says ask markers live in the organization home with one subdirectory per profile.
- **State files are read and installed as plain files on every platform (#48 round 4).** A link or a swapped path is refused where `O_NOFOLLOW` does not exist, the state lock is never taken through a link, and a write or Ask-journal publish installs only the temporary file it wrote, not a substitute at the same name.
- **State files are read only when plain and small, and a write never follows a link (#48 sweep).** A symlink or a FIFO named `*.json` no longer gets followed or blocks the queue, a file over 16 MB is refused before it is read, the temp name of a write is created exclusively, a failure to clear or record the retry marker no longer changes the outcome the caller sees for an answer, and `recovery.py` reports a lock it cannot check as unknown and a damaged `recovery` path as a refusal instead of a traceback.
- **A safe recovery workflow for corrupt plugin state (#48).** New `recovery.py` (stdlib, next to `needs.py`) has `diagnose`, `preserve` and `restore` for `hidden.json`, `pending-release.json` and `bluf.json`. Diagnosis separates corrupt or truncated files, valid JSON in an unsupported shape, unsafe paths and an active writer, and prints counts only. `preserve` copies the exact bytes into `plugin-data/unbl0ck/recovery/` (0700 directory, 0600 files, never deleted). `restore` is a dry run by default, refuses unverified, symlinked, loose-permission or wrong-store backups, never clears the lock, copies the current bytes aside first and swaps atomically; a failure leaves the store as it was. Legacy null or empty hidden versions stay valid. The operator guide and state table describe it.
- **The disclosure matrix now marks Kanban as read across profiles, and a queue response uses one settings snapshot (#42 round 4).** Hermes keeps one Kanban store shared by every profile, so a card blocked from one profile reaches the queue of another and `kanban` reports `cross_profile: true`. `build_queue` takes one settings snapshot for the model-use flags, the matrix, whether summaries are attached and the coverage notes, so a settings refresh between reads can no longer give `bluf_enabled: true` next to `summary: false`. Tests run the real Kanban store from two profiles, expire the settings between reads, compare each `search` and `cross_profile` flag with what the real readers and search do, and check end to end that a settings fault sends nothing to the model.
- **The disclosure docs separate shared filed items from per-profile watched folders and list every persistent file (#42 round 4).** Agent-filed items live in one shared folder every profile reads, while each profile reads only the `outside_dirs` its own settings configure. The README write list and the architecture state table now also name `chat-backfill.json`, `pending-release.json` and the empty `.state.lock` file, and a test scans the code for every state file name and fails until both documents list it.
- **Docs now match behavior in ten places (#42 sweep).** Done on an agent-filed item is restorable for 15 minutes (not a deletion); the filing profile is provenance and scopes `dedupe_key`; Ask restart markers live under `ask/<profile>/`; `GET /card` does bound its identifiers; a chat's summary text is the 480-character queue excerpt; cards are grouped by source before priority; a `card` mismatch on an Ask job is 404 but the job id alone answers when `card` is omitted; request-validation limits are 422; `jobs.py` includes the Ask journal; a stale "last 20" comment is gone. A test pins the corrected statements.
- **The disclosure matrix says watched-folder and filed items are read across profiles (#42 review).** Agent-filed items sit in one shared folder and the queue has no reading profile, so `outside` is now marked cross-profile in `needs.SURFACES` and the architecture table, and tests check the column against what the readers actually return for two profiles.
- **A source-by-surface disclosure matrix, in code, payload and docs (#42).** `needs.SURFACES` and `disclosure_matrix()` say which sources can reach the model provider by summary, Ask or search, and which are read across profiles; `GET /queue` returns the live matrix as `disclosure` (booleans only), and `docs/architecture.md` carries the table, kept equal to the code by a test. New tests send synthetic secrets through every summary and Ask input, check that only kanban, filed/folder and chat items are summarized, that Ask refuses non-Kanban references, that a settings fault turns every model path off, and that summary caches stay partitioned by source and profile and survive concurrent saves and corruption. The independent Security verdict for the exact head is not part of this change.
- **The detection corpus now fails when the configured name stops matching (#40 round 4).** Nine corpus cases contain the principal's actual name (gates, waiting-on, possessive, lowercase, a relayed order, a report, another person's name and a look-alike word), and a test breaks name matching on purpose and requires those cases to go red.
- **A widened chat window no longer sends the asks it newly reaches to a model (#40 round 4).** A chat found only because `chat_window_days` was raised past what an earlier read covered (for example 1 to 7 days) is now marked as backfill and kept out of automatic summaries, as the setting's description promises; the flag stays on it across refreshes. The queue keeps a small `chat-backfill.json` (the oldest time read and at most 1000 chat ids, no chat text), and the docs list it.
- **Chat reads are bounded by work, read in one snapshot, and never reported as all clear when sessions were left unread (#40 round 4).** Databases without session activity columns are ordered and windowed by their newest message, so expired chats no longer spend the 500-session cap ahead of a current ask. The session list and the omitted count come from one read transaction, the per-session continuation check is a single pass, and a chat read that exceeds its work budget is reported as a failed source. Cached summaries of chats the cap left unread are kept. Desktop shows NOT ALL CLEAR with the count and an open coverage note (and a QUEUE INCOMPLETE chip), and the CLI and slash summaries say the queue is incomplete instead of "Nothing is blocked on you".
- **The chat reader refuses what it cannot safely open, keeps a shared database under one name, and survives bad numbers (#40 round 4).** A FIFO or device in place of `state.db` is reported as a failed chat source instead of blocking the refresh, and a database that cannot be inspected is a failed source rather than silently skipped (only a missing one is optional). When several profile names reach one database, the name that already holds a dismissal or cached summary keeps it, so adding an alias no longer resurfaces a hidden chat. `chat_window_days` accepts only 1 to 90 as documented (anything else, including `"²"` or a huge digit string, uses 14), infinite stored times and settings no longer raise, and `profile.yaml` is read under a 64 KB bound whose signature comes from the opened file.
- **Chat detection lists one database once and reads only a plain, small profile.yaml (#40 sweep).** Two profile names pointing at one `state.db` counted its chats twice; a symlinked or oversized `profile.yaml` was read for the seat name. A link or a file over 64 KB now falls back to the profile name.
- **Chat coverage no longer claims more than was read or summarized (#40 review).** Full-text search reports chat sessions the scan cap left unread and is marked partial. A corrupt chat database or unreadable settings now shows a failed chat source with a plain note instead of "Chats checked: last N days". Chats found only because `chat_window_days` reaches past 14 days are marked backfilled and are never sent to a model for an automatic summary.
- **The queue says how far back it looked and what it cannot see (#40).** The payload carries `coverage`: the chat window actually read, sessions checked and left unread, chats skipped by the group-name and owner rules (counts only), and fixed sentences on what an empty list does not prove (older chats, unnamed group asks, non-English asks, Kanban comments). Desktop shows them under the list. New `chat_window_days` setting (default 14, 1 to 90) is a bounded read-only backfill: at most 500 sessions per profile, hidden items stay hidden, no duplicates. `tests/ask_corpus.py` is a labeled corpus (39 cases across sources, platforms, five languages, name forms, indirect and group asks) whose test pins the known false positives and negatives so a fix or a regression both show up.
- **The search page now ties hits to the queue it searched, and the guides match it (#45 round 4).** The page counts matches that no longer sit on a loaded card, says to search again after a queue refresh, and runs under node tests for the click, rendered coverage, stale versions and late answers. The operator guide states the 200-item cap per source and what the page shows; the verification map lists the executed search tests.
- **Full-text search reads without writing, counts what it skipped once, and reports damaged dismissals (#45 round 4).** Search no longer deletes expired Done records or stale waits, or creates state folders on a fresh home. A full queue of 200 healthy records is complete, failed reads and overlapping watched folders use or count the shared 200-item budget once, a dismissal entry with no version is reported, and terms may be split between a card's title, app or chat name and its body.
- **Full-text search now reports a damaged dismissal list, counts folder files beyond the 200-file window as not searched, and ignores a late answer for an old query (#45 sweep).** A corrupt `hidden.json` used to read as "nothing dismissed" with no error, so dismissed cards became searchable; files past the folder window were neither searched nor counted; a slow response could write its hits and error after the query had changed or been cleared.
- **Search is tested at the profile boundary and for preserved state (#45 review).** Tests show full-text search finds exactly the chats the queue shows for every profile under the Hermes home, returns ids, versions and sources only, and that the Search full text button changes only its own search state, so typed answers, drafts and open conversations are left alone.
- **Full-text search spends its budget on cards a person can see and counts only what it examined (#45 review).** Chats, live prompts and filed items dismissed at their current version are dropped before the 200-item limit and before any full-text expansion, so 200 hidden chats no longer hide a visible one. All watched folders share one read budget of 200 files (the rest are reported as not searched) instead of reading 200 per folder. A watched-folder file cut at its read limit is counted as cut and makes the result partial. Password prompts are counted as skipped, not as searched.
- **Full-text search counts text the chat and prompt readers already cut, and expands only what it searches (#45 review).** A term beyond the 20,000-character cap of a chat message or live prompt now shows as `items_cut` and `partial` instead of a clean "no match". The readers expand full text for the first 200 items of a source only; the rest are still counted as not searched, so a 205-chat inbox no longer does 205 full-text expansions to report 200 searched.
- **Search says what it searches and can go deeper on request (#45).** The filter box is labelled as searching titles and previews of the cards loaded here. A separate **Search full text** button makes one `GET /search?q=` call that reads the stored text of chats, live prompts and filed or folder items, at most 200 items and 20,000 characters each, 8 terms and 200 query characters. Results carry the source and item version, and a coverage line reports what was searched, not searched, cut off or skipped (password prompts are never read) and which sources failed. It is read-only, never calls a model, never runs on a timer, and leaves typed answers and open conversations alone.
- **The Pocket pack, local list and surface matrix now tell the truth about what they omit and withhold (#47 round 4).** `omitted.unread_sources` counts each unreadable source once and ignores capacity and cleanup notices (a full 200-item filed queue is no longer an unread source, while a cut folder listing still marks the pack incomplete); a negative `limit` selects no cards instead of all but the last; the local list and the Pocket pack replace a password prompt's text with a fixed notice; Desktop's subtitle no longer says a source failed when the notice is only a limit; the matrix states per action when a Desktop card leaves and where a password prompt's excerpt is visible; a test now runs `--json` and checks the serialized queue.
- **The Pocket pack now says when a source could not be read (#47 sweep).** A queue with failed sources exported as an empty pack that looked like "nothing needs you". The pack carries `complete: false` and a count in `omitted.unread_sources`; never the error text.
- **Limited surfaces say what they leave out (#47).** The CLI and local slash list now end with "Not listed here: N stuck, M answered", and an empty list with stuck or answered cards is no longer reported as an all-clear. The remote slash command adds the same counts and still carries no title, text, name, id or command. The Pocket pack gains an `omitted` object (asks beyond six, stuck, answered, and where to look) of counts only. The operator guide has a five-surface matrix and `tests/test_surface_contract.py` pins common item order and identity plus every intentional difference.
- **The capability matrix and its guide now match behavior (#33 round 4).** A Kanban card explains the missing TL;DR when Ask is off; Context is classified as the Context panel or Full text view (chats and non-password prompts have it), folder cards count as routed by their Act in line, and the guide separates automatic one-line summaries from interactive Ask, limits the card-leaves-on-next-poll claim to sources that can observe it, lists the Kanban Pocket choices, and documents the 502 for a failing provider. The route guard now pins method and path pairs.
- **A capability matrix says what each source can do and why not (#33).** The queue payload publishes `capabilities` (Kanban, chats, live prompts, pairing, filed items, watched folders) separating built features from intentional safety restrictions and from real gaps; the operator guide shows the same table and a test keeps them equal. Cards without TL;DR now say "TL;DR is not offered here" with the reason (password prompts and pairing are never sent to a model). No inline reply, send or approve was added: replies still happen in the original surface under its own authorization, and a test pins the set of write routes.
- **Ask restart markers are contained, bounded, durable and scoped per profile (#35 round 4).** The journal refuses symlinked or foreign directories, creates files 0600 in a 0700 directory with unique temp names, reads without following links or blocking, rejects implausible or oversized records, fsyncs before reporting success, and holds the 256-file cap under a lock that spares live foreign jobs.
- **A poll never claims a job is gone when storage could not be checked (#35 round 4).** An unreadable journal reports unknown, a job whose worker is alive in another process stays pending, deleted jobs cannot be resurrected, failed deletes are reported honestly and retried, and Ask reads and deletes now require the matching card.
- **Consuming an Ask job now keeps the job when its saved record cannot be deleted, Ask records over 256 KB are treated as corrupt without being read, and the summary-retry table is bounded (#35 sweep).** A failed delete on consume used to drop the job from memory while the saved reply stayed on disk and was recovered as the same job; a version that had used all its retries was never pruned from the summary table.
- **Ask restart markers distinguish unavailable storage from a missing marker, and one bad entry no longer disables them (#35 review).** The model call starts, and a discard reports success, only after the marker is verified absent; storage that cannot be examined counts as unknown. A dangling symlink named like a record is judged without being followed, is removed by housekeeping and no longer makes every new marker fail.
- **Deleting an Ask job reports failure honestly and the restart-marker cap holds (#35 review).** When the saved record cannot be removed (for example a read-only directory), `DELETE /card/ask/{job}` now answers 500 and leaves the job as it was instead of reporting success and letting the next GET recover the saved answer. A new marker first evicts the oldest ones that no live job owns, so the 256-file cap holds across gateway restarts rather than overshooting until the next throttled prune.
- **Ask survives a gateway restart without resending (#35).** Each Ask job leaves an owner-only restart marker (0600 in a 0700 directory, 256 files, 15 minutes, no card or answer text) so a poll after a restart reports `pending`, `complete`, `failed`, `unknown` (sent, outcome not knowable) or `not_submitted` (nothing left the machine); the plugin never resends and Retry is the human's decision. Job ids answer only for their own card, `DELETE /card/ask/{job}` removes a job at once, corrupt or symlinked markers read as unknown, and an unwritable directory falls back to memory. New opt-in `ask_persist_replies` (default off) keeps finished answers on disk for the retention window.
- **Answer drafts are kept per backend connection too (#34 round 4).** A draft typed for a card on one backend no longer shows up, or gets submitted, on another backend that has the same card id and version.
- **One Ask conversation is bounded and expires on a mounted card (#34 round 4).** A conversation keeps at most 100 messages and 200,000 characters and says when older ones were dropped; an expired conversation leaves the screen and is never resent.
- **An Ask request whose conversation is evicted or expires now reports it (#34 round 4).** The card shows that the conversation was dropped from session memory and offers Retry, instead of clearing Thinking and discarding the reply without a word.
- **Ask conversations are kept per backend connection (#34 round 4).** The same card id on another backend or profile never shows or resends a conversation, and closing a connection removes its conversations.
- **An unknown Ask job no longer claims a gateway restart (#34 round 4).** The card now says the answer is no longer available because the gateway restarted or the result expired, since the server cannot tell the two apart.
- **Ask advice goes out of date when the card text changes (#34 round 4).** A recovered conversation is marked old, and Use as answer is disabled, when the title, question, owner or comments change, not only when a new block event appears.
- **A superseded Ask request stops polling and cannot hand Retry its job (#34 review).** When the running session is evicted while the card is mounted and a second question starts, the older request now exits at its next step instead of recording its job id over the newer one or appending its answer to the newer conversation.
- **Ask conversations survive filtering, source outages and route remounts (#34).** The conversation, a running request and its job are kept in bounded Desktop session memory (100 conversations, 30 minutes, never written to disk), so returning to a card shows the answer without a second model call. Recovered conversations stay bound to their question version and a late response cannot overwrite newer work. Reload still clears them by policy.
- **Resolving a filed item reports success once its record is gone (#46 round 4).** If the stale Not for me marker cannot be removed after the record was deleted, resolve still returns resolved, with a note, instead of an error that invites a pointless retry.
- **Filed keys only match our own records, and never guess (#46 round 4).** Matching by `dedupe_key` skips stray JSON files and records whose name and id disagree, refuses to overwrite or delete when several records claim one key (including explicit global keys and duplicate profile matches), still stops when an unreadable record might hold the key, and the tool description and README say a global key is resolved with `dedupe_scope: "global"`.
- **Resolving a filed item also drops its "Not for me" marker, and a `dedupe_key` over 120 characters is refused instead of cut (#46 sweep).** A cut key let two different long keys collide into one record; the marker of a resolved record stayed in `hidden.json` until the cap evicted it. A damaged `hidden.json` is left untouched.
- **Records filed by 0.6.0 before profiles existed keep their Done and Not for me state (#46).** Adopting an ownerless record into a profile keeps its version when the content is unchanged, so an unchanged refile no longer resurfaces finished work; key-only resolve finds it. Tests start from the exact record 0.6.0 wrote.
- **Filed dedupe keys are profile-scoped by default (#46).** `unbl0ck_file` takes `dedupe_scope` (`profile` or `global`); the same key in two profiles now files two items and one profile can no longer replace or resolve another's by key. Records and replies carry `dedupe_scope` and `profile`; legacy records are adopted in place by their own profile without resurfacing a local Done.
- **Folder scans and dismissal stores stay bounded and honest (#37 round 4).** Files already marked Done or Not for me no longer use up the 5,000-entry scan budget, so each finished page reaches the next one. The scan reports a time overrun or a listing that failed midway without losing the files it had found. Reads backfill past unreadable files, stop at the 2-second read budget with a notice, and summarise repeated read errors. The folder dismissal cap scales with the number of watched folders (up to 8), the store is written as compact UTF-8 and trimmed to stay under its 16 MiB read limit, and the hidden count and the omission of hidden files from the listing are reported. Folders and the recursion flag are read from one settings snapshot.
- **The hidden and pending-release caps now drop the oldest entry, not the alphabetically first (#37 sweep).** Both stores were written with sorted keys, so after a reload "oldest first" meant "first in the alphabet": a recent dismissal could be evicted while an old one stayed, and folder paging progress (hash keys) was lost at random. They now keep insertion order on disk.
- **The folder scan's time budget also covers empty directories (#37 review).** The deadline is checked before each queued directory is opened, so a tree of empty folders can no longer scan past the 2-second budget without the "stopped after" notice.
- **Folder paging keeps its progress and overlapping roots lose nothing (#37 review).** Folder Done records have their own 5,000-entry bound in `hidden.json` (other dismissals stay at 1,000), so finishing a backlog past 1,200 files no longer evicts the earliest completions and cycles back to them; a file is claimed by an overlapping root only when it is actually shown, so an older file under a separately watched child folder is no longer dropped.
- **Hiding the first page of a watched folder no longer strands older files (#37).** Done and Not for me files no longer use the 200-file window, ties order by path, and the queue reports how many older files are waiting. Optional `outside_recursive` reads nested folders within depth, entry and time limits, never following symlinks; the filed-item cap reports counts and how to continue. Source files are never moved.
- **Each dismissal has its own token, so a stale or replayed Undo restores nothing (#36 round 4).** Not for me and Done return a random token that names that one dismissal; the record version is no longer a token, a consumed token cannot clear a later dismissal, an Undo whose hide no longer applies restores nothing, and a late response in the page cannot replace or fail a newer dismissal. `hidden.json` entries now carry the token after the version (older entries still load).
- **Done records are validated before they are deleted, and cleanup is reported and bounded (#36 round 4).** Only a file named for its record id that an agent filed and that has a real timestamp is ever deleted; a boolean, non-finite or foreign file is kept and reported, a clock that stepped back restarts the window instead of stranding the record, a removal that fails is counted in the queue errors without blocking other actions, and the scan reads at most 1000 entries in 2 seconds.
- **Re-filing or undoing a Done record respects the 200 cap (#36 round 4).** Changed content for a Done record and Undo of Done are refused with a clear message when 200 active records already exist.
- **A summary survives Done and a slow older request cannot hide a newer one (#36 round 4).** Summaries of retained Done records are kept so Undo does not ask the model again; request start order, with sub-second times, decides which summary wins.
- **The README and operator guide now describe Done as recoverable (#36 round 4).** A filed record is kept for 15 minutes (at most 25), Undo is offered for both kinds, the disk bound is 200 active plus 25 retained, and cleanup runs on the next poll, filing or action while UNBL0CK runs, with no background timer.
- **A late summary or a late refresh can no longer act on newer state (#36 sweep).** Desktop's queue refresh after an answer or Done now waits for any load already in flight and reads again, so a response read before the action cannot put the card back. A summary request for an older question no longer replaces the summary of a newer one, and pruning the summary cache keeps summaries saved after the queue it judged was read.
- **Undo no longer clears a newer Done, and a failed write stays retryable (#36 review).** A Not for me token for an older version cannot remove a Done recorded for a newer one, and when both markers exist the hidden marker is cleared first so a failed second write leaves the Done token valid for a retry.
- **Undo names the dismissal it undoes (#36 review).** A Done now returns a `token` and Desktop sends it (or the hidden version) with `/unhide`; an old Undo can no longer clear a newer Done or hide, and a filed item dismissed twice (Done in one tab, Not for me in another) is restored by either Undo clearing both markers. Callers without a token behave as before.
- **Done on outside items is local and recoverable (#36).** Done on an agent-filed item now keeps its record, marked done, for 15 minutes (at most 25 records) instead of deleting it, so Undo works; folder Done is unchanged. Desktop keeps a history of the five latest dismissals with separate Undo buttons, announces expired Undo windows, and says "nothing to restore" when an item changed or aged out. The card states that Done does not send or complete anything in the original app; the agent's `resolve` stays the permanent path. Re-filing identical content keeps a Done item hidden, changed content resurfaces it. The stored text of done records is deleted after the window and never printed in errors.
- **Answer version rules hold on one settings snapshot, C1 controls are refused and board spellings agree (#41 round 4).** `require_answer_version` is decided by the answer write from the settings it captured (428, nothing written; a release without a version stays 400), C1 controls and line separators in card references are rejected instead of being stripped into another card, `DEFAULT` and `default` no longer conflict, and the tests isolate `HERMES_KANBAN_HOME` so they cannot write into a real installation.
- **Answers carry an explicit version precondition and every route bounds identifiers (#41).** `POST /kanban/answer` now reports the block `version` it applied and whether the caller sent one (`versioned`). Unversioned comment-only answers keep working but get a `Warning` header; the new `require_answer_version` setting (off by default) turns them into a 428 before anything is written. An empty version is a 400. `/card`, `/hide`, `/unhide`, `/outside/done` and the answer route share one 300-character, no-control-character limit, and a malformed, non-Kanban or conflicting card id is a 400 rather than a silent retarget. Stale and retried answers never duplicate a comment or release a newer block.
- **Stale desktop responses are now tested (#32 round 4).** The Full text tests track each effect and run its cleanup, and check that an older response arriving after a newer request is ignored, including a late failure.
- **The Pocket pack says what it cut and which block it answers (#32 round 4).** Each card's text is bounded (4,000 characters, 20,000 per pack) and a cut ends in `[truncated]`; cards carry `truncated` and `warning`, and the pack reports `omitted` and `complete`. Kanban actions name the board and the block, and block-loop cards are no longer offered an unblock the plugin would refuse.
- **Ask redacts more and sends the decision first (#32 round 4).** Digit-only values under credential keys (`password=123456`), credential keys spelled with `\u` escapes, and secrets that follow many leading `{}` objects are now redacted, and an exhausted JSON scan withholds what it cannot check instead of copying it. The card's workspace path is removed wherever it is repeated, the block reason is budgeted ahead of the description, cut fields end in `[truncated]`, the card data stays valid JSON, and your question is sent whole. Card history is read with limited queries instead of loading every event and comment.
- **A watched-folder file that cannot be read is reported, not skipped (#32 round 4).** A file that changed while it was read now adds a "retry" line to the folder's errors instead of vanishing, and a hostile message (for example thousands of nested MIME parts) is reported as that one file's error while the rest of the folder still loads.
- **A filed item's version follows its content, not the session that filed it (#32 round 4).** Refiling identical content under the same key from another session now keeps the same version, so a dismissal is not undone by the refile. The latest filing session is still recorded on the item.
- **Answering a card is one write: a refused answer leaves nothing, a failed release is always recoverable (#32 round 4).** Posting the answer and releasing the card now share one Kanban transaction, so a card blocked again in between returns the 409 with no comment behind it. A release that raises (a locked database, a changed Hermes helper) is treated like one that returns false: the comment stays, the failed-release marker is recorded and the queue offers the retry. The marker is reserved before anything is written, so a busy state lock refuses the answer instead of losing the marker, and a cleanup error after a successful release no longer turns the success into a failure. Duplicate detection looks only at comments made since the current block, so an earlier block's identical answer no longer suppresses a new one.
- **Filed and watched outside items are exact about identity, versions and the folder they read (#32 round 4).** A `dedupe_key` over 120 characters is refused instead of being cut to a key that collides with another; a title or action location that is blank inside its limit is refused instead of filed invisible. Resolving by id now needs the version that filing returned, and a version that no longer matches (another agent refiled it) keeps the record. A watched file's version includes a digest of its text, so an equal-length edit with a restored timestamp is a new item again. Watched folders are listed and read relative to one directory handle opened without following links, so swapping the folder for a link mid-scan cannot redirect a read, and a filed record purged between listing and reading is no longer reported as invalid.
- **Live prompts show their true end, say when they are cut, and report hook failures (#32 round 4).** A live prompt over 20,000 characters keeps its last 2,000 characters in the wait record, so the excerpt is the real question rather than a middle slice. A cut prompt, and an older record holding a full 4,000-character prefix, now mark the item truncated so Full text warns. A prompt's version covers its text, profile, session and process, so replacing a record under the same request id makes an old Full-text request stale. A wait record that could not be written, or a resolved one that could not be removed, is retried on the next poll and reported as a failed Prompts source until it works.
- **Chats are scoped to you, read within a budget, and versioned by their text (#32 round 4).** With owner ids set, a chat with an unknown source but a stranger's user id is no longer shown. A chat message is read from its end, at most 100,000 characters, so a huge message cannot stall polling, and the ask check and group-name check look at the same tail. A chat's version now includes a digest of its text, so a rewritten message makes an old Ask or Open-full-text request stale. Opening full text looks at that one chat or prompt only: a malformed reference opens nothing, and an unrelated broken profile no longer turns a deleted chat into a retry.
- **Chat, prompt, outside and pairing sources refuse links and report folders they cannot list (#32 round 4).** A profile folder, a profile database, the `plugin-data` folder or the data folder that is a symbolic link is skipped and reported instead of followed to another Hermes home, and a denied directory listing is a failed source rather than an empty one (it used to look like "no chats", "no prompts" or "no match" and could return a 404 for an existing prompt). A damaged pairing pending file now shows as a failed Pairing source, not as zero requests.
- **State files are never read or written through a link, a pipe or an oversized file (#32 round 4).** A symbolic link in place of the data folder, its subfolders, the lock file, a state file or a temporary file is refused, a FIFO or device cannot hang a read, files over 16 MiB are treated as unreadable, a new temporary file starts at owner-only mode, and a replace blocked briefly by a reader on Windows is retried.
- **Hidden and recovery state keep the right entries (#32 round 4).** An older tab can no longer replace a newer "Not for me", the caps evict the oldest entry rather than the smallest name, an updated recovery marker moves to the newest position, a finished release clears only its own block's marker, and a full recovery store refuses a new marker and says the release needs doing on the board instead of silently dropping an older one. Entries in a shape this version does not write are refused rather than rewritten.
- **Summaries follow the card text and redact before they cut (#32 round 4).** A cached summary is shown only while the card's title, text, owner and comment count are what it was written from, a damaged `bluf.json` is left for repair instead of being overwritten, a summary that is not text is ignored, and summary inputs (title, owner, comment authors) are bounded. Secrets are redacted before text is cut for a summary, Ask or chat excerpt, and Full text keeps the first line's indentation.
- **Answers are matched to the right block, even within one second (#32 round 4).** The newest block is chosen by event order, not by a clock that can step back, and a comment made just before a re-block no longer counts as the answer to the new block.
- **Bot titles, filed records and Ask turns are read and cut safely (#32 round 4).** A seat's title is found only under `ui_meta`, re-read when the file is replaced (not just resized), and a bad or oversized profile file gives the fallback name. A filed record that cannot be read is no longer treated as absent when filing or resolving, and an Ask turn is cut at the 20,000 characters the API accepts instead of 8,000.
- **Ask follow-ups can no longer poison a conversation, double-ask or outlast their limit (#32 round 4).** An over-long or refused follow-up is not kept in the history and its text comes back to the box, each Ask sends the card version and a request ID that Retry reuses, and the 150 second limit now covers the first request, every wait and a finished reply. Undo for Not for me and outside Done, and clearing a sent answer draft, no longer wait for the queue refresh.
- **A summary that keeps failing now stays capped (#32 round 4).** When the summary job table grew past 500 entries, pruning dropped failures that had cooled down and with them their attempt count, so a bad card could be retried forever. Pruning now removes only stuck pending jobs, and a documented hard cap of 5000 entries evicts the oldest first.
- **Outside Full text and Done tell absent from unreadable, and short multi-line text is reachable (#32 round 4).** Full text for a watched-folder or filed item is now looked up directly instead of from the newest-200 poll window, so an older file can still be opened. A missing item stays 404, while an unreadable folder or a corrupt filed record is 503 and is never deleted by Done. A short message whose line breaks were flattened now offers Full text, and the excerpt label comes back whenever the excerpt is what is on screen.
- **Ask and answer requests are validated and admitted before any work (#32 round 4).** Ask rejects malformed message lists (unknown roles, extra keys, non-text content, a trailing assistant turn) instead of dropping them, decides capacity before reading the card, refuses a question about a card that was blocked again (409), returns the same job for a repeated request id, and re-checks the Ask and summary settings right before the model call so a turned-off feature sends nothing. An answer needs a board and a card id, and POST Pack writes the same pack it returns.
- **Summaries stop when switched off, terminal output is cleaned, and an empty ask list no longer reads as all clear (#32 round 4).** A cached summary is no longer attached to cards once summaries are disabled, the CLI and slash output strip control characters from every field, and the CLI, slash command and Desktop say that stuck or answered cards are listed instead of "Nothing is blocked on you" or ALL CLEAR. The README now describes the real queue order, and GET Card applies the same 300-character limit as the POST models (documented in the architecture guide).
- **Full text shows the whole chat message or live prompt (#32).** Polling still carries a 480-character tail, now labelled; opening Full text reads the complete record (up to 20,000 characters) for that version via `GET /source/text`. Stale, missing and unreadable sources report errors with retry; password prompts are never expanded and nothing is sent to a model.

## 0.5.1 (2026-11-14)

- **Interrupted Ask responses are recoverable.** Retry polling the same completed job without repeating model work. Completed-result retention is bounded and follows completion order, so a slow job is not immediately evicted by newer requests.
- **Unreadable settings fail closed.** Read errors, parser error markers and loader import failures cannot widen chat visibility, model disclosure or answer identity. Concurrent refreshes share one settled read; another caller's repair cannot erase an in-flight caller's fault. Configured behavior resumes after repair.
- **Typed answers survive a source outage.** Session drafts retain their original question version; a late completion from an old card cannot erase a newer draft. Drafts remain in memory for up to 30 minutes after editing and do not survive a page reload.
- **Mail selection excludes named MIME parts.** Inline parts with filenames cannot replace the message body; alternative and related message structures retain their body-selection rules.
- **Canonical guides cover recovery and review.** Operator, architecture and verification references document the actual limits. A signed external-PR Security Hermes relay is included for owner activation; acknowledgements do not count as review approval, and live activation remains unverified.

- **Recovery survives a temporary outage.** Failed Undo keeps its retry control and cannot submit twice while pending. Failed answers refresh the queue immediately so a posted answer with a failed release shows its recovery action. Long TL;DR conversations keep their displayed history while respecting the API's 50-message transport limit.
- **Failures stay visible and recoverable.** Corrupt source records, schema/config failures and folder limits mark the queue incomplete. Unreadable prompt records survive inspection, stale cleanup cannot hide healthy prompts, and visibility writes refuse corrupt state. Summary fallback status is explicit; model work has bounded admission, rejected submissions cannot strand jobs, and Ask expiry works without a new request.
- **Find cards in a large queue.** Search titles, previews, apps and references, or filter by source. Typed answers survive filtering, and the status count still covers the whole queue.
- **Read and recover in place.** Every card has a keyboard-accessible full-text toggle. Full-text and Context failures have retry controls; folder Done can be undone for 12 seconds. Long subjects and unbroken text wrap on small screens, and text composition no longer submits an unfinished answer or Ask.
- **Exports show the right content.** Plain-text attachments and attached messages never stand in for an HTML-only draft body. Oversized exports disclose the 256 KiB preview limit.
- **Faults stay honest.** The CLI and status chip no longer imply an empty queue is complete when a source fails. Combined `--json --pack` keeps stdout valid JSON. Disabling the Desktop plugin ignores late responses and cannot restart its polling.
- **One click gets the bottom line.** "Ask about this card" is now **TL;DR**: clicking it asks your model, straight away, what the card wants from you and what to pick, in plain words and under 80 words. Follow-up questions still work in the same panel.
- **Ask no longer comes back empty on reasoning models.** With a 900-token cap, MiniMax M3.1 Flash spent the whole budget thinking and returned no text, which showed as "The model returned an empty answer". The cap is now 4000, inline `<think>` blocks are dropped, and a reply with no answer text says so and suggests a retry.
- **Real asks stop vanishing from the queue.** A negation now counts only in the same clause and only in the three words right before the ask, so "Cannot proceed: needs CEO approval to merge" and "Needs your approval. Not urgent." are listed. After the ask, only "is not needed/required" cancels it. New phrasings are recognised: "approval from Ada", "can't deploy without your approval", "Please approve…", "need the human to…". A relayed order ("CEO says: …") still counts as a stop unless it asks for *your* approval or decision. On the live board, 16 of 209 blocked cards are now listed, up from 10.
- **Fewer false chat asks.** Question marks inside URLs, sign-offs like "Anything else you need?", questions the turn answers itself ("Why did it fail? Because…"), "which option was faster" and an archived decision packet no longer count as asks.
- **"Answer, keep blocked" cards stay in the queue.** Before, answering a card without unblocking it made it vanish, so it stayed blocked with no way back from UNBL0CK. Now it stays listed as `answered` (counted apart from new asks, no model summary) with a **Release (unbl0ck)** button that unblocks it without posting a second comment.
- **The shortcut shows what it will do.** When your answer says to keep the card blocked, ⌘/Ctrl + Enter keeps it blocked; the ⏎ mark now moves to **Answer, keep blocked** and the hint says so. The Release button no longer shows a shortcut it does not have.
- **Docs say what actually happens.** Failed summaries are retried after 10 minutes and the page polls every 45 seconds; listing pairing requests prunes expired ones, as `hermes pairing list` does; the CLI points to the `/unblock` page.

## 0.4.6 (2026-11-11)

Fixes from the hackathon roast (two independent audits).

- **Your answer goes to the question you read.** The desktop sends the queue item's version with each answer. If the card was blocked again after you opened it, the answer is refused (HTTP 409) and nothing is posted.
- **A failed unblock can be retried.** When the answer posts but the card won't unblock, the card stays in the queue marked `release_failed`. Answering it again retries the release without posting the answer twice. The marker lives in `plugin-data/unbl0ck/pending-release.json`.
- **Every blocked card is listed** (from PR #1): cards with no recorded ask show as `stuck`, with the reason. Answered cards leave the queue in both tiers. Stuck cards don't get a model summary, so a long stuck list doesn't trigger a model call per card.
- **State files are safe across processes.** `hidden.json`, `bluf.json` and `pending-release.json` are written under a file lock, so the dashboard and the agent plugin no longer drop each other's writes. A failed write no longer leaves a temp file behind.
- **The owner filter fails closed.** With `owner_user_ids` set, a gateway chat whose user is unknown is no longer shown or summarised.
- **`GET /pack` is read-only.** `POST /pack` writes `pocket-pack.json`.
- **No personal names in shipped files.** Tests and the design canon use generic names.
- **CI runs the tests in the pinned Hermes runtime** with a throwaway `HERMES_HOME`, and fails if any test is skipped.
