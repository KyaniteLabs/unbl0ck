# UNBL0CK design canon

This folder is the single source of truth for how UNBL0CK looks, sounds and behaves on every surface: Hermes Desktop, the X55 handheld and the Bravia TV. `tokens.json` holds the values; this file explains the rules. When a surface disagrees with this folder, the surface changes, not the canon. Proposed changes to the canon go to the UNBL0CK owner, the Claude Code session that builds the Desktop plugin.

## Data contract: read it, never re-derive it
- `GET /api/plugins/unbl0ck/queue` returns `{generated_at, count, hidden, items[], errors[], ask_enabled}`. Each item has `source` (`kanban`|`chat`), `id`, `version`, `title`, `ask`, `why`, `since`, `owner`; kanban items add `board`, `task_id`, `priority`, `status`, `block_kind`, `block_recurrences`; chat items add `profile`.
- `GET /api/plugins/unbl0ck/card?id=kanban:<board>:<task>` (or `?board=&task_id=`) returns the read-only card context: body, comments, parent/child graph, workspace/branch/PR, recent events, last run outcome, attachments and `created_by`.
- `POST /api/plugins/unbl0ck/card/ask {id, messages[]}` asks the configured model about one card and returns `{reply}`. The card context is injected server-side and marked untrusted; the model never acts. Disabled when `ask_enabled` is false.
- `GET /api/plugins/unbl0ck/pack` returns the same queue as a Pocket pack (`version: 1`, `mode: "unblock"`, up to 6 `decide` cards with `options[]`) and writes nothing. `POST /api/plugins/unbl0ck/pack` returns the same pack and also writes `<data_dir>/pocket-pack.json`, which is UNBL0CK's own file and never the gadget plugin's `pocket-pack.json`.
- `POST /api/plugins/unbl0ck/kanban/answer {board, task_id, text, release}` comments as you (the configured principal) and unblocks the card. `POST .../hide {id, version}` hides an item until its version changes.
- A gadget never writes Kanban directly and never decides what "needs you". It renders these endpoints.

## Look: the whole app, not one screen
Every screen of every surface uses this language: home, menus, settings, chat, and the UNBL0CK queue. The Desktop page is the reference. `reference/desktop-hero.png` and `reference/desktop-full.png` show it, `unbl0ck.css` is its exact stylesheet (generated by `desktop/build.py`), and `tokens.json` gives the same values in a form any language can read.

**Layers, bottom to top:** base `#05070a`, then the ASCII contour field, then the fx tints and scanlines, then grain, then content. The field is the signature. Port the algorithm in `tokens.json.layers.field` exactly: same bumps, drift, levels, glyphs and alpha, so a TV and a handheld show the same terrain moving the same way. Scale only the cell size to the screen.

**Colour roles:** amber is the one primary action per card or screen. Cyan is data and the active state. Green is OK and done. Magenta is for faults only, plus the hearts and the glitch split. Steel is structure. The field's mint, signal, violet, rose and gold appear only in the field and the mascot ramps, never on UI chrome. No other accent colours.

**Type:** Rajdhani 700 uppercase for titles, buttons and card titles. Rajdhani 500 for body. Share Tech Mono for every number, label, eyebrow, meta line and ticker. The fonts are in `fonts/` (OFL).

**Components** (exact specs in `tokens.json.components`):
- Corner L-brackets on the screen.
- Four-colour ticks over an eyebrow written `// A / B · C`.
- The glitch ASCII wordmark `UNBL0CK`, or the app's own name in the same ANSI-shadow treatment.
- Chamfered stat tiles and cards with a 52px index box.
- Chamfered buttons with a key chip.
- A mono ticker, a hazard-stripe divider, and section heads with a rule.

Chamfers are cut corners, never rounded corners. Nothing in this language has a border radius.

**Motion** (`tokens.json.motion`):
- Cards boot in staggered, and a scan sweep marks hover/focus.
- `■ UNBL0CKED` flashes green when a card is done.
- The cursor blinks and the wordmark glitch runs on a 5.2s cycle.
- With FX off or reduced motion, everything holds still: one field trace, no grain or glitch, the mascot shows one idle frame.

**Focus is the hover:** on a TV or handheld, D-pad focus takes everything Desktop hover does (amber frame, scan sweep, button cyan). Focus must always be visible.

**Scale, don't redesign:** a 10-foot TV and a 5-inch handheld change sizes, cell size and how many cards show. Never the structure, colours, type roles or chamfer shapes.

## Mascot: the Nous girl
- Source: the official Hermes Agent `nous-girl-white` art (MIT, (c) 2025 Nous Research). Always carry the attribution and the "independent of Nous Research" line from `../NOTICE`.
- Never hand-draw or regenerate her. Use `mascot/nous{96,80,64}.json`, picking the widest width that fits. For a new width, run `python3 mascot/conv.py COLS`.
- Frames, mood rule, per-mood colour ramps, schedules and events are all in `tokens.json`. Ramps are selective and never a full rainbow. Orange is allowed on the mascot, as worried = gold → amber → rose.
- With reduced motion or FX off, show one still idle frame.

## Sound
- X55's `x55_pocket.py` is the origin. The values in `tokens.json` are a sample-exact port, so keep them identical everywhere: 22050 Hz mono, `move`/`ok`/`warn`/`err`.

## Logo
- FINAL (v22, locked 2026-11-09). Eight of Wands × realistic tourmaline; never orange. Files live in `assets/logo/`:
  - `alive-dark.webm` / `alive-dark.mp4`: animated logo (loop). `still-dark.png`: 1200² still and the video poster.
  - `banner-dark.png`: 3600×1200 banner.
  - `icon-512/128.png`: four wands; `icon-64/32.png` and `favicon.ico`: two-wand small mark.
  - `apple-touch-icon.png` (180) and `icon-maskable-512.png` (art inside the 80% safe circle).
- Don't retouch these by hand; changes go back through the source pipeline and need the maintainer's sign-off.

## Reference implementation
- `desktop/src/plugin.src.js` covers the field renderer (`heightAt`/`paintField`), mascot renderer, ramps, SFX and the event bus. Port its behaviour, not its React.
- `unbl0ck.css` is generated from it; never edit the copy. Run `python3 desktop/build.py` after changing the source.
- To check a surface, put a device screenshot next to `reference/*.png`. A neutral observer should say they are the same product.
